# Scripts (phase 2)

The verification harness and the runtime adapters land here in phase 2 of the plan (`docs/design/2026-10-12-extraction-analysis.md`, section 10):

- `verify-slice.sh`: the tier runner skeleton (slice id resolution, one log per run, `run()` that records every step, `RESULT=`/`LOG=`/`FAILED:`, a `tiers.jsonl` row, a slot queue for a shared resource, self-pinning to the harness commit) with the tiers' steps read from the project configuration.
- `must-run/`: "a named test must actually run and pass" for Go, pytest and Playwright.
- `record-usage.sh`, `wake.sh`, `hold-wait.sh`, `stall-check.py`, `stale-procs.py`, `next-ready.py`, `status.py`: budget and flow telemetry, on the `harness` library. Requirements carried over from the first run's fixes of 2026-10-12: timestamps are parsed by one helper that accepts ISO 8601 and integer epochs (`hooks/lib.sh` `sw_epoch` already does; port its tests from `test_budget_ts.py`); `wake.sh` never discards a detector's stderr and prints `STALL-CHECK-ERROR` on a non-zero exit; slice ids match `slice-\d+[A-Za-z0-9-]*$` everywhere (port `test_stall_check.py`).
- `protected-diff.sh`, `redteam-protected.sh`: protected files enforced at the diff, and the corpus that proves it.
- `new-worktree.sh`, `pin-t2.sh`, `milestone-push.sh`, `install-schedules.sh` (launchd and cron adapters).
- `install.sh`, `check-drift.sh`: copy-install with provenance stamps for runtimes without plugins.

Already here: `dashboard-loop.sh` (rebuilds the dashboard of `../dashboard/` every 30 seconds and runs the project's publish command; installed with the dashboard by `install.sh --dashboard`), `release.sh` (bump, test, validate, commit, tag, push, marketplace entry), `claude-usage-statusline.py` (a Claude Code `statusLine` command: the plan windows from the status line's `rate_limits`, the only documented source, appended to `<state dir>/metrics/usage-claude.jsonl` when a value changes or every `SW_CLAUDE_READING_MINUTES`; configure it as `python3 -I <copy of the script>`; tests in `tests/test_claude_usage_statusline.py`), `collect.py` (method chapter 19: completion read from pids, tier logs, branch heads and committed handoffs for every open allocation; tests in `tests/test_collect.py`), `install.sh` (copy-install of the skills, and of the agents for Claude Code without the plugin, into a project or the user's directories; never symlinks, never overwrites without `--force`), `survey.py` (method chapter 17: the project inventory and the `--next` dispatcher, no writes; tests in `tests/test_survey.py`), `check-design-docs.py` (method chapter 14 lints: an ARCHITECTURE.md change cites a decision, INDEX.md rows within the review limit, frozen specs without TODO; a T0 step in projects with living design documents; tests in `tests/test_check_design_docs.py`), and, generic as copied from the first run: `run_logged_check.py`, `summarize_check.py`, `automation_errors.py`. Under `runtimes/codex/`, the Codex adapter (`README.md`): `dispatch.sh` (one `codex exec` worker process per allocation, in its worktree and a sandbox by role, resumable), `status.sh` (the worker processes and their return lines), `agents.py` (the role agents rendered as `.codex/agents/*.toml`, and the parity check), and `implementer.rules` (execution-policy rules for a worker's trusted worktree).
